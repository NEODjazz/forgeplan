# ForgePlan — спецификация продукта v0.9 Alpha
Дата: 24.10.2026. Статус: исходная спецификация / working draft.

## 1. Назначение и объём

Открытая система календарно-ресурсного и корпоративного управления проектами.
Целевая база сравнения: настольный Microsoft Project Professional 2024 и
корпоративные сценарии Project Server Subscription Edition. Исторические
возможности других редакций добавляются отдельными строками после проверки.
Матрица — предварительный перечень, не результат исчерпывающей сертификации.
Ссылки на исходные материалы: docs/REFERENCES.md.

Три режима: локальный проект без сервера; корпоративный веб-клиент;
настольный клиент с локальным редактированием и синхронизацией с сервером.
Семантика планирования общая. Паритет веба и desktop проверяется сценариями,
а не визуальной похожестью интерфейсов. Публикация на GitHub/хостинг не выполнена.

## 2. Пользователи

Руководитель проекта: расписание, базовый план, прогноз, ресурсы, публикация.
Участник: назначения, фактическая работа, табель, комментарии.
Ресурсный менеджер: доступность, ставки, компетенции, межпроектная загрузка.
PMO: шаблоны, портфели, контроль качества, приоритеты, отчётность.
Руководитель: риски, сроки, бюджеты, решения по портфелю.
Администратор: организация, права, SSO, интеграции, аудит и восстановление.

## 3. Функциональные требования

F-01. Проект: ID, код, название, владелец, организация, статус, календарь,
валюта, часовой пояс, дата отчёта, режим планирования, версия и версия движка.
F-02. Иерархия: WBS, порядок соседей, indent/outdent, суммарные задачи,
вехи, шаблоны. Итоговые значения вычисляются из потомков; циклы родителей запрещены.
F-03. Связи: FS/SS/FF/SF, лаг/опережение, рабочие и календарные единицы,
проверка циклов и диагностируемые конфликты. Межпроектные связи — отдельная фаза.
F-04. Календари: базовый, проектный, ресурсный, задачи; рабочие интервалы,
смены через полночь, исключения, версии, DST и правила пересечения доступности.
F-05. Движок: ASAP/ALAP, планирование от начала/конца, ограничения SNET/SNLT,
FNET/FNLT/MSO/MFO, дедлайны, ручные задачи, split tasks, elapsed durations,
ранние/поздние сроки, total/free float, driving dependencies и несколько путей.
F-06. Назначения: work/material/cost/generic resources, единицы назначения,
максимальная доступность, фиксированные work/duration/units, effort-driven,
профили работы, overtime, committed/proposed booking.
F-07. Выравнивание: перегрузки по периодам, приоритет, резерв, split/shift,
ограничения диапазона, предварительный просмотр и откат. Эвристика объявляется
явно; математическая оптимальность не обещается.
F-08. Факт: actual/remaining work, actual start/finish, completion variants,
дата отчёта, перенос оставшейся работы, защита утверждённого факта.
F-09. Базовые планы: именованные снимки расписания, назначений и стоимости;
сравнение baseline/current/actual; неизменяемость опубликованных снимков.
F-10. Затраты: ставки с периодами действия и таблицами, fixed/per-use costs,
начисление start/prorated/end, time-phased cost, бюджеты, EVM и валюта проекта.
F-11. Интерфейс: редактируемая таблица и синхронный Гант, связи мышью,
масштаб, фильтры, группировки, пользовательские столбцы, клавиатура,
undo/redo, календарь, resource/task usage, network diagram, печать и PDF.
F-12. Сервер: портфели/программы, корпоративный пул ресурсов, custom fields,
шаблоны, фазы и gates, заявки проектов, приоритизация, capacity planning.
F-13. Совместная работа: draft/published revisions, обсуждения, уведомления,
журнал изменений, сравнение версий, approvals, табели и делегирование.
F-14. Интеграции: REST/OpenAPI, webhooks с подписями и повторной доставкой,
OIDC, экспорт BI; Jira/GitLab и HR/ERP — после стабильного публичного API.
F-15. Файлы: версионированный открытый формат с миграциями, XML/CSV/Excel;
MPP — изолированный адаптер. При импорте каждый неподдержанный элемент
попадает в отчёт. Запрещён молчаливый импорт с потерями.
F-16. Расширяемость: формулы в ограниченном интерпретаторе, версии схемы
custom fields, ограниченные плагины. Выполнение произвольного кода запрещено
по умолчанию. Совместимость VBA не входит в базовый план.

## 4. Подключение и согласованность

Desktop: добавить URL организации → OIDC Authorization Code + PKCE в системном
браузере → выбрать организацию/проект → скачать снимок. Refresh credentials
хранятся в системном хранилище секретов, не в файле проекта.
Web: BFF-сессия в HttpOnly/Secure/SameSite cookie; OIDC на серверной стороне.
Сервер валидирует issuer, audience, signature, exp и права каждой команды.
SSO не заменяет проверку доступа к проекту и организации.

Каждая команда несёт command_id и base_revision. Сервер атомарно проверяет
права и версию, меняет доменную модель, рассчитывает её, фиксирует изменения,
результат и аудит. Повтор того же command_id с тем же содержимым возвращает
исходный результат; с другим — ошибку. Устаревшая версия даёт 409.

Автоматическое слияние допустимо для независимых изменений после проверки
инвариантов. Связи, календари, назначения и ограничения не сливаются слепым
last-write-wins. Настольный клиент хранит outbox и базовый снимок; при конфликте
показывает base/local/server и требует выбора. Расчёт клиента предварительный;
публикуемый результат сервера авторитетен. Несовместимая версия движка
блокирует публикацию до обновления или серверного перерасчёта.

## 5. Нефункциональные требования

N-01. Один Rust-движок, детерминированный результат при одинаковых входе,
версии алгоритма и календарных данных. Денежные величины не используют float.
N-02. Самостоятельная установка, резервное копирование БД и вложений,
восстановление с проверкой. RPO/RTO определяет оператор; целевые значения
выбираются с инфраструктурой, не гарантируются библиотекой.
N-03. Изоляция организаций во всех запросах и фоновых заданиях; least privilege,
аудит, управление сроками хранения, безопасная загрузка вложений и экспорт.
N-04. Локализация RU/EN, часовые пояса, клавиатурная работа, целевой WCAG 2.2 AA.
N-05. Цели для будущего benchmark: полный пересчёт 10 000 задач/30 000 связей
без ресурсов p95 ≤ 500 мс на выделенном 4-vCPU стенде; редактирование больших
таблиц с виртуализацией. Это цели, не измерения текущего прототипа. Контрольный
стенд, browser version и данные фиксируются перед приёмкой.
N-06. API versioning, schema migration, structured logging, metrics/traces,
health/readiness, cancellation и ограничение дорогостоящих расчётов.

## 6. Текущий выпуск 0.9 Alpha

JSON schema/migration, WBS/minute calendar, resources/capacity, basic work modes,
cost/baseline/actual/EVM, leveling preview/apply, SQLite multi-project workspace,
org roles + OIDC/PKCE, publish/audit/timesheets, offline CLI, XML/CSV subset.
Каждая функция ограничена описанным alpha-поднабором. Все целевые F/N требования
не считаются закрытыми: см. ROADMAP_STATUS.md и COMPATIBILITY.csv.

## 7. Критерии приёмки следующего релиза R1

AC-01. Настольный файл и веб-сервер рассчитывают эталонные планы одинаково.
AC-02. Иерархия минимум 5 уровней; запрет циклов родителей; корректные rollups.
AC-03. Сохранение/открытие сохраняет ID, порядок, поля, связи, календарь и версии.
AC-04. Добавление FS/SS/FF/SF и отрицательного лага корректно меняет расписание.
AC-05. Ошибка/цикл оставляет последнюю подтверждённую версию неизменной.
AC-06. Гант и таблица синхронны; undo/redo работает для составных операций.
AC-07. DST, leap years, holidays, рабочие интервалы и split tasks проверяются
отдельным календарным набором после перехода на минутную модель.
AC-08. Для заявленного поднабора MS Project есть эталонные файлы и отчёт diff;
отличия документированы до объявления совместимости.

## 8. Открытые решения

Название/бренд; окончательная лицензия и политика внешних вкладов;
приоритет отраслевых сценариев; требования к масштабу и offline веба;
поддерживаемые версии Project/MPP; форматы BI/ERP и требования размещения.
Предварительные решения: Apache-2.0, self-hosted, все три desktop ОС,
Rust core/server + TypeScript web, OIDC, PostgreSQL, без обязательного облака.
