# Семантика минутного движка 0.3

## Единицы и календарь

WorkDuration и Lag — целые рабочие минуты. Календарь задаёт start date/time,
фиксированное UTC-смещение, 7 списков рабочих интервалов, праздники и исключения.
Приоритет: исключение даты → праздник → день недели. Интервалы упорядочены,
не пересекаются; начало < окончание; 24:00 разрешено только как конец.
Ночь задаётся двумя днями. IANA, DST, секунды и leap seconds не реализованы.

Timeline хранит рабочие сегменты с префиксной рабочей координатой. Нулевая
координата — первый доступный рабочий момент не ранее старта проекта.
`start_at(k)` при границе сегментов выбирает следующий рабочий старт;
`finish_at(k)` — окончание предыдущего рабочего сегмента. Например, при
Mon–Fri 09:00–17:00 и старте в пятницу 09:00: start_at(480) — понедельник
09:00, finish_at(480) — пятница 17:00. Поэтому нельзя сравнивать только числа
рабочих координат для всех видов зависимостей.

Нулевая веха — событие в start_at(k). Она может оказаться на следующем рабочем
интервале после FS-предшественника, закончившегося ровно на границе. Это
объявленная политика прототипа; она не означает полного совпадения с Project.
Summary хранит min/max действительных timestamps потомков, включая вехи,
и рабочий span; его late/float = null, critical=false. Пустые summary не
расширяют span родителя с работой. Summary links/date rules запрещены.

## Зависимости и ранний проход

FS/SS сравнивают начало преемника с целевым временем; FF/SF — окончание.
Якорь предшественника: finish для FS/FF, start для SS/SF.
Ненулевой lag переводится по рабочим сегментам: положительный — к моменту
завершения соответствующей рабочей длительности, отрицательный — к моменту
начала отступа. Нулевой lag сохраняет фактический timestamp якоря.
До начала проекта отрицательный lag не создаёт отрицательных start coordinates.

Для каждого ребра получается монотонная функция S_j >= f_ij(S_i), с переводом
в ближайший допустимый start/finish instant. Проект сортируется топологически,
каждая задача получает max(0, date lower bound, incoming edge requirements).
Все циклы отклоняются. Ограничения с потенциально допустимыми циклическими
SS/SF-сетями отдельно не решаются. Алгоритм не является resource scheduler.

## Ограничения

| Тип | Смысл | Нерабочий момент |
|---|---|---|
| SNET | start >= requested | Ближайший рабочий старт не раньше |
| SNLT | start <= requested | Последний рабочий старт не позже |
| FNET | finish >= requested | Ближайший допустимый рабочий finish не раньше |
| FNLT | finish <= requested | Последний рабочий finish не позже |
| MSO | start == requested | Ошибка, если точный рабочий start невозможен |
| MFO | finish == requested | Ошибка, если точный рабочий finish невозможен |

Одна основная constraint на задачу, плюс независимый deadline.
У вех finish-ограничения используют её start/event semantics. Точный constraint
не подменяется округлением. Невозможное сочетание зависимостей и верхней границы
отклоняет всю командную группу, сохраняя модель и историю.

Пример FNET: час работы, ближайший finish должен быть позже субботы 12:00.
При пятидневке он может оказаться в понедельник 09:01, со стартом в пятницу
16:01. Понедельник 09:00 — начало нового сегмента, а не окончание положительной
рабочей минуты. Такой результат явно следует из целоминутной модели.

Deadline сравнивается с фактическим рассчитанным finish и даёт warning.
Он не является hard bound, не переносит план и не изменяет float. Это может
отличаться от настроек расчёта критичности Microsoft Project.

## Поздний проход и резервы

T = максимальная координата окончания обычных задач/вех. Верхняя граница
каждой задачи — min(T-duration, own date upper bound). Далее обратный
топологический проход инвертирует монотонную функцию каждого ребра бинарным
поиском максимального допустимого start. Использовать постоянный вес ребра
через разрывы календаря было бы некорректно, особенно для SF/FF.
Total float = latest_start - earliest_start, в рабочих минутах. Critical: float=0.
Графовый проход линейный; обратное инвертирование добавляет log горизонта,
а поиск сегмента — log числа сегментов. Сам календарь строится лениво по дням.

## Объяснения

reasons содержит старт проекта/первый рабочий интервал, явное ограничение,
связи с требованием, равным рассчитанному ES (все определяющие ties), факт
пересечения нерабочих интервалов и просрочку deadline. Это объяснение текущего
расписания, не diff к прошлой версии и не доказательство оптимальности ресурсов.

## Границы

2000 задач, 20000 связей, 64 уровня, 48 млн рабочих минут и не более 300000
календарных дней скана, даты 1970…9999. Сложные/дальние календари могут упереться
в scan limit раньше лимита рабочих минут. Все ошибки оставляют Editor неизменным.
